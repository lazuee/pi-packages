- The tool is one action enum over the whole `agent-desktop` CLI; keep a new action on the enum rather than a second tool, and map it in `buildArgs` with the CLI's dashed spelling.
- Refs are snapshot-scoped. Any read that could renumber them belongs before the act, and every act must answer with a fresh snapshot rather than the CLI's bare "Done".
- The optional fields in `parameters` are not optional per action: validate the required ones and name the missing one, so a bad call does not reach clap as `INVALID_ARGS`.
- Send `window_id` only to `snapshot`, `screenshot` and `press`; a ref carries its own window and the ref commands reject the flag. `mouse_click` is the exception and takes it only with `window_xy`.
- A window-relative `mouse_click` is that pair, and each half is useless alone, so both are named at the call. It posts to the window and stays headless; only the absolute `x`/`y` form forces the pointer. The frame to measure against comes from `screenshot --window-frame`, whose pixels are divided by the reported `scale_factor`.
- Headless is the default and `headed` is per call, so never force the pointer for an action that has a semantic path. Upstream makes this a rule, not a hint: `--headed` is for the user's explicit request, never as recovery from a headless failure.
- `render` is the whole agent-facing contract: a value is clamped there, a tree node leads with its ref, and a CLI failure is lifted out of JSON into its message and suggestion. Keep it plain text.
- Discovery must probe for an answer, not an executable: the launcher dies on a missing native binary, so trust a candidate only after `list-apps` returns 0. The tests gate the same way — on `cliAnswers()`, never on `prebuilt/bin/agent-desktop` existing — because that launcher is committed and present on every platform while only the build machine's native pair is shipped. CI is Ubuntu against a darwin build, so a file test runs the suites there and parses an empty stdout.
- A `describe.skipIf` body still executes when the suite is skipped, so anything a suite does while describing (starting a session) needs its own `built &&` guard, not just the surrounding skip.
- `prebuilt/` is the only local bin discovery uses. `upstream/npm/bin` is where `link:cli` also copies, but for upstream's own tests, not for calls.
- A sandbox name is lowercase, digits and hyphens, so it is passed bare — a `--` there would end flag parsing before the options that follow and clap would reject them.
- Tests run under plain `bun test`, not vitest: `#src` resolves through the package `imports` map, `expect.poll` is a local helper, and a module with state is re-imported under a cache-busting query instead of `vi.resetModules`.
- `tests/cli-contract.test.ts` parses every action through the real launcher and is what catches a wrong flag. `npm run link:cli` copies the `prebuilt/bin/` binaries into `upstream/npm/bin/`, which is where the checkout's launcher looks.
- `prebuilt/` is a committed mirror of the upstream npm package: launcher, lib, package.json and the release binaries. It is what discovery runs first, so neither the submodule nor a global install is required. No Rust toolchain is needed to work here. `npm run link:cli:build` is the only thing that compiles: it runs `cargo build --release` in `upstream/` and rewrites the whole mirror. Run it after moving the submodule, and commit the result; the two are synced by hand on purpose so neither drifts silently. Which upstream commit a pair came from is the submodule gitlink itself, so a sync needs no separate stamp.
- Nothing avoidable is written inside `upstream/`, so `git status` stays clean there. Two things still are: `upstream/npm/bin` (where the launcher looks) and `upstream/package.json` pinning `commonjs`, which upstream does not track. `tests/setup.ts` is a `bunfig.toml` preload that runs `link:cli` in both a `beforeAll` and an `afterAll`, because upstream's `wrapper.test.js` treats that bin directory as scratch and leaves it empty, and `bun test` runs no npm `pretest`.
